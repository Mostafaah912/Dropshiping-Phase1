# فهرست ایرادات و برنامه اصلاح

## ۰. قواعد هر جلسه کاری
- فقط بخش «مرحله N» همین فایل و فایل‌های نام‌برده در همان مرحله را بخوان؛ کل پروژه را دوباره اسکن نکن.
- برای هر مورد: اول تست بازتولیدکننده (Mock/SQLite)، بعد اصلاح. «داده قدیمی است» فقط با شاهد.
- سندباکس اینترنت ندارد؛ هر چه فقط روی وردپرس واقعی قابل تست است را در گزارش جدا بنویس.
- متن‌های کاربر مشتری فارسی ساده و بدون اصطلاح فنی. هیچ دامنه/کلیدی hardcode نشود.
- Nonce + capability + sanitize + escape همه‌جا. همه سوییت‌های قبلی سبز بماند.
- پایان هر مرحله: نسخه هر پلاگین تغییرکرده patch/minor بالا برود، وضعیت موارد همین فایل به‌روز شود (⬜→✅ + یک خط شاهد)، lint، commit، push، و گزارش کوتاه: چه چیزی تغییر کرد، چه چیزی فقط روی سایت زنده تست‌پذیر است، آیا آپدیت پلاگین مبدا/Full Sync/ریست لازم است.
- تصمیم‌های بخش «تصمیم‌های باز» را خودت نگیر؛ اگر مرحله‌ای به یکی نیاز داشت از پیش‌فرض پیشنهادی استفاده کن و در گزارش صریح بنویس.

## ۲. تصمیم‌های باز (پیش‌فرض پیشنهادی)
- D1: وقتی سایتی در مبدا غیرفعال شد، محصولات Import‌شده‌اش چه شوند؟ پیشنهاد: هیچ تغییری؛ فقط سینک و Import قطع شود.
- D2: قیمت مبدا قیمت فعال (شامل حراج) است. پیشنهاد: همان بماند.
- D3: گرد کردن قیمت نهایی؟ پیشنهاد: گزینه در تنظیمات، پیش‌فرض خاموش (گزینه‌ها: بدون گرد، ۱۰۰، ۱۰۰۰، ۱۰٬۰۰۰).
- D4: محصول/تنوع بدون قیمت در مبدا؟ پیشنهاد: Import آن ردیف partial با پیام روشن، نه قیمت ۰.
- D5: محصول چنددسته‌ای؟ پیشنهاد: فعلاً فقط آخرین برگ؛ در README مستند شود.
